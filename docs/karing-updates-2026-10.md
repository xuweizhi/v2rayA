# Karing 近期功能借鉴落地（2026-10-27）

基于本地 `/data/karing` 截至 `47f97692` 的更新，补齐以下五项功能。服务端、定制核心和 Web 页面需要一起构建、升级；旧核心无法提供此次新增的备用 DNS 和分组 DNS 路由行为。

## 1. 订阅专属节点 DNS

入口：订阅列表 → 修改 →「使用本订阅专属 DNS 解析节点地址」。

- 从 Clash YAML 的 `dns.proxy-server-nameserver` 读取解析器列表；新导入的订阅带此字段时默认启用，已有订阅保留原来的开关。
- 手工输入优先于订阅提供的列表；手工留空则跟随订阅，关闭开关则恢复默认节点 DNS。
- 支持 UDP、TCP、DoT（`tls://`）、DoH（`https://`），最多八个地址。列表按顺序尝试；主解析器超时、连接失败、SERVFAIL 或 REFUSED 时切换，备用列表中的直连查询共享四秒预算。
- 只生成当前连接节点主机名的精确匹配规则，不接管其父域名或默认 DNS。解析节点地址始终直连，避免通过尚未连通的节点解析自身地址。
- 同一主机名出现在多个活动节点中时，DNS 策略必须一致，包括使用默认 DNS 的情况；发生冲突时拒绝生成配置。
- DoH/DoT 执行真实加密查询和证书验证；bootstrap 后保留原主机名用于 SNI 和验证。备用解析器的缓存与其他策略隔离。
- TinyTun 使用独立 DNS 路径，当前暂不支持此设置；连接域名节点时会明确报错。请关闭该订阅的开关，或使用 redirect/tproxy。

## 2. 订阅节点属性过滤

入口：订阅列表 → 修改。

- 可选择协议集合，以及对节点名或服务器主机名应用包含、排除正则。
- 协议条件与正则条件同时生效；不选择协议即不限制协议。
-「预览过滤结果」针对当前已保存的节点显示总数和匹配数，不下载订阅、不修改节点。
- 保存后需要刷新订阅才能应用过滤。已被旧条件过滤掉的节点无法在本地预览中出现，重新下载时才会重新评估。
- 后端校验正则、字段和 DNS 地址；格式错误直接返回，不静默忽略。

## 3. 按代理组执行 DNS 诊断和自动配置

入口：首页「网络诊断」，或 DNS 设置中的自动配置区域。

- 可指定代理组；诊断也支持直连。只有已连接节点的组具有可用的测试入口。
- 每个活动组使用独立的本地 SOCKS 测试入口，路由优先于用户分流规则；正式 DNS 请求也路由到相同组，包含组内负载均衡和前置代理。
- UDP 直连、TCP、DoT、DoH 均验证真实 DNS 应答；加密协议验证证书，不把 TCP 接通或普通 HTTP 200 当成成功。
- UDP DNS 经代理测试时使用 TCP，直接 UDP 应答截断时重试 TCP。
- 自动配置要求直连和指定代理组均有成功结果，才替换 DNS 规则；全部失败时保留旧配置。结果展示实际分组路径。

## 4. 前置代理组

入口：顶部代理分组菜单 → 展开组 → 设置 → 前置代理组。

- 先连接前置组，再为落地组选定前置组。组内节点连接按「本机 → 前置组 → 落地组 → 目标」转发。
- 支持多级依赖；拒绝自身引用、间接循环和不存在的组。作为前置组使用时不能直接删除该组。
- 使用原生传输层 `dialerProxy`。共享节点按组复制出站配置，未设置前置代理的其他组保持原路径；观测器跟随各组实际出站。
- 支持原生 VMess、VLESS、Trojan、Shadowsocks、SOCKS、HTTP 出站。外部插件和 Hysteria2/TUIC/AnyTLS 等不经过这一传输接口的出站会明确报错，尚未宣称支持所有协议组合。
- 配置生成失败时旧进程保持运行；重载失败时恢复相关设置，并在需要时尝试恢复旧核心。恢复失败会返回错误。

## 5. 首页概览与快捷入口

显示当前代理组、所选节点或负载均衡数量、核心状态、透明代理配置模式、实时上下行速度；提供流量详情、网络诊断和网络设置入口。概览支持桌面与窄屏布局。
